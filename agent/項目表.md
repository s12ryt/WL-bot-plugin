# 項目表

## 根目錄

- `.github/workflows/ci.yml`：Java 25 完整測試與建置，保存報告與 JAR artifacts；`smoke-test` matrix job（paper/folia）下載 JAR artifact 後以真實伺服器跑 `ci/SmokeTestDriver.java` 端到端煙霧測試。
- `.github/workflows/release.yml`：標籤／手動發布，核對版本、測試建置並上傳 JAR 與校驗碼至 Releases。

- `ci/SmokeTestDriver.java`：JEP 330 單檔煙霧測試驅動（不進正式 JAR）：fill v3 API 下載 Paper/Folia 26.3、兩次啟動伺服器、本機 mock Telegram Bot API、JDBC 注入 PENDING 申請、斷言完整審核流程；依賴 fat JAR 內的 SQLite 與 Gson。

- `agent/`：需求、任務、架構與操作紀錄。
- `src/main/java/`：外掛正式 Java 程式。
- `src/main/resources/`：`plugin.yml` 與預設 `config.yml`。
- `src/test/java/`：JUnit 5 單元與 SQLite 整合測試。
- `build.gradle.kts`：Paper API、SQLite、Gson、JUnit 5 與 fat JAR 建置設定。
- `settings.gradle.kts`：Gradle 專案名稱。
- `gradlew`、`gradlew.bat`、`gradle/wrapper/`：固定版本 Gradle Wrapper。

## 正式模組依賴

- `WhitelistBotPlugin`：組裝設定、SQLite、Telegram 背景工作、事件監聽器與關閉順序。
- `config/`：驗證 Bot token、管理員 ID、冷卻、資料庫相對路徑與 polling timeout。
- `domain/`：玩家 UUID 與名稱值物件。
- `queue/`：SQLite 待審／冷卻狀態、順位、Telegram message ID 與跨重啟持久化。
- `presentation/`：產生 Minecraft 原生拒絕畫面的繁中順位與冷卻文字。
- `minecraft/`：處理 `ProfileWhitelistVerifyEvent`，並經 Global Region Scheduler 寫入原生白名單。
- `review/`：驗證 Telegram user/chat、套用通過／拒絕狀態轉移。
- `telegram/`：Bot API HTTP 契約、callback codec、通知重試、審核訊息刪除、offset 與工作執行緒生命週期。

## 主要流程

- 原生白名單拒絕 -> `WhitelistLoginListener` -> `LoginRequestService` -> `SqliteQueueRepository`。
- 未通知申請 -> `PendingNotifier` -> `TelegramHttpGateway` -> 記錄 message ID。
- Telegram callback -> `TelegramPollingWorker` -> `TelegramReviewProcessor` -> `ReviewService`。
- 通過 -> `ScheduledWhitelistGateway` -> Paper/Folia Global Region Scheduler -> 原生白名單。
- 拒絕 -> SQLite `COOLDOWN` -> 15 秒後玩家重連建立新申請。
