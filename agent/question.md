# 白名單審核外掛驗收標準

## 已確認需求

- 伺服器平台：Paper 26.3 與 Folia 26.3。
- Java 版本：25。
- 伺服器必須開啟原生白名單。
- 未在白名單的玩家連線時，自動建立一筆待審申請。
- 相同玩家已有待審申請時不得重複送出 Telegram 訊息。
- 玩家在 Minecraft 原生的連線拒絕畫面看到目前排隊順位與待審總數。
- Telegram 機器人將申請送到設定的單一管理員聊天，訊息具有「通過」與「拒絕」按鈕。
- 只有設定的 Telegram 管理員 user ID 可以操作審核按鈕。
- 按「通過」後，外掛在 Paper/Folia 合法的全域執行緒加入原生 Minecraft 白名單。
- 按「拒絕」後不加入白名單，玩家進入 15 秒冷卻；冷卻結束後再次連線可重新申請。
- 審核成功後自動刪除原本的 Telegram 申請訊息。
- 待審資料、順位、冷卻與 Telegram 訊息 ID 使用 SQLite 持久化，伺服器重啟後仍保留。

## 安全與失敗處理

- Bot token、管理員 user ID 與 chat ID 僅存在外掛 `config.yml`，不得寫死於程式或測試。
- 非授權 Telegram 使用者按按鈕時不得變更隊列或白名單。
- 重複或過期的按鈕操作不得重複審核。
- Telegram 暫時傳送失敗時，待審申請不得消失，並應在背景重試未通知的申請。
- Telegram 刪除訊息失敗不得回復已完成的審核結果，但必須留下警告紀錄。
- 外掛關閉時必須停止 Telegram long polling 與背景工作。

## 操作假設

- GitHub 自動化：使用者確認在 `s12ryt` 帳號建立公開的 `WL-bot-plugin` 儲存庫，推送專案並執行 CI；另提供建置 JAR 至 Releases 的 workflow。

- 建議伺服器使用 `online-mode=true`，避免離線模式 UUID/名稱可被冒用。
- 玩家獲准後需自行重新連線；Minecraft 已顯示的拒絕畫面無法由伺服器即時刷新。
- Telegram Bot API 僅允許刪除通常未滿 48 小時的訊息；超時訊息可能無法自動刪除。
